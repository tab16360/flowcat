# 磁盘写入提醒验证

日期：2026-10-21。数据来自本机短时测量，不构成所有设备的资源上限承诺。

## 测量范围

`Tests/DiskAlertBenchmark.swift` 为独立的优化编译程序，直接复用真实 DiskSampler、DiskAccumulator 和 DiskAlertEngine。两组各每 10 秒采样一次、持续 60 秒（7 次快照），分别关闭和开启提醒；同时运行，系统其他活动可能带来噪声。此测量不包含 SwiftUI 窗口、网络采样、系统通知投递及原有历史持久化，数值不是整个应用的内存或 CPU。

| 指标 | 关闭 | 开启 |
|---|---:|---:|
| 平均 CPU，占一个核心 | 0.229% | 0.217% |
| 进程常驻内存 | 11.24 MB | 11.44 MB |
| 每次规则判断平均耗时 | 0.003 ms | 0.136 ms |
| 进程计数新增磁盘写入 | 0 字节 | 0 字节 |
| 分钟缓存跟踪应用数 | 0 | 16 |

CPU 差异小于此次测量噪声，不能解读为开启后反而省 CPU。此次常驻内存差值约 0.20 MB；不能外推为固定开销。

## 容量压力测试

模拟 512 个应用每 10 秒同时写入，连续重放两小时，共 720 轮；这是加速重放，不能把程序运行时接近一个核心的 CPU 占用当作实际后台占用。首次测得单轮规则判断平均 1.63 ms，最大 9.05 ms；进程常驻内存相对启动增加约 4.42 MB（包含模拟数据、运行时分配和引擎），新增进程磁盘写入为 0 字节。缓存上限为 512 个近期写入应用，每应用 61 个分钟槽；无写入一小时后回收。

## 正确性与存储

最终本地 159 项检查通过，包签名校验与实际打包二进制的隔离更新替换检查通过。

新增独立规则检查覆盖持续窗口、连续提醒抑制、重启冷却、休眠／无效采样、单进程不可用、多个规则合并、跨日预算、忽略、暂缓及恢复、关闭不分配、缓存上限、过期回收及恢复再触发。沿用 PID＋内核启动时间基线，应用辅助进程在原采集层按应用路径合并。

磁盘集成检查验证：真实采样建立基线、保存恢复、暂停恢复、损坏／未来版本历史保护，以及没有新采样时第二次 save 不改变历史文件修改时间。网络和磁盘 save 均增加变更标记；磁盘保存成功后统一更新保存时间，避免独立采样和网络联动保存重复写入。原有全历史 JSON 格式保持兼容，尚未改成数据库或按日分片。

告警设置存 UserDefaults；最近 40 条提醒与去重状态存 `disk-alerts.json`，仅发生新提醒时写入。分钟曲线不落盘。现有历史的正常周期保存仍然存在，不能把上述 0 字节宣称为整个应用永不写盘。

## 界面与限制

已编译并渲染浅色、深色、510 点窄窗口的设置、空状态和应用曲线详情，以及原有磁盘面板入口。示意数据仅用于渲染。原生 UI 自动化连接超时；系统通知权限弹窗、真实通知点击回到应用和多显示器鼠标操作仍需人工验收。通知投递错误会显示在提醒窗口，未授权系统通知时仍保留窗口内记录。

构建和安装包采用现有本地签名方式；不改变已有网络／磁盘历史格式，不自动重启被提醒的进程。
